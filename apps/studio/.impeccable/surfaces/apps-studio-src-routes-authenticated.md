# Multi-tenant administrative surfaces

- Scope/mode: Operate; `/select-workspace`, authenticated context switcher, access-denial states,
  `/platform`, and reason-bound support mode.
- Audience/job: tenant owners, admins, and members must enter and continuously recognize the correct
  organization; CRV operators must inspect tenant health and perform attributable client support.
- Primary actions: select/switch context, recover from permission/plan/quota denial, review access
  requests, enter/exit support, and operate clients without cross-context leakage.
- Proof/content: server-confirmed tenant name, role/capabilities, subscription/quota facts,
  non-PII tenant counts, support reason/expiry, and mutation outcomes.
- Direction: extend the incumbent restrained navy/gold Studio shell and component vocabulary. Tenant
  work remains calm and familiar; platform/support context is structurally distinct and persistently
  labeled, not merely recolored.
- Memorable moment: context switching confirms the destination, clears stale tenant data, then
  places focus on the new workspace identity; support mode pins an unmistakable banner with exit.
- Constraints: Brazilian Portuguese, WCAG 2.2 AA, keyboard/focus/screen-reader behavior, 320px,
  zoom, reduced motion, light/dark/system themes, no impersonation or payment claims.
- Unresolved decisions: none blocking; code-first applies to this approved extension for this
  session and is not stored as a global workflow default.
